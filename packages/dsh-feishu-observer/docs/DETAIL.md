# 飞书连接看板

**一句话：** DSH 与飞书的连接状态，直接显示在 DSH 窗口右下角；断线自动排查修复；每次启动 DSH 都会给飞书发一条“已上线”。

## 你会看到什么

窗口右下角常驻一个小胶囊：

- 🟢 **飞书 · 已连接**：授权、事件长连接、桥接发送器、开放平台接口全部正常。
- 🟠 **飞书 · 部分异常**：连接还在，但某个环节心跳偏慢或授权即将过期。
- 🔴 **飞书 · 连接中断**：影响收发消息的环节失败，胶囊会闪烁，看板自动展开。
- ⚪ **飞书 · 检测中**：首次加载或 DSH 宿主正在重启。

点击胶囊展开完整看板：

| 区域 | 内容 |
| --- | --- |
| 连接检查 | lark-cli 工具、飞书授权、事件长连接、桥接发送器、开放平台接口、消息入站、上线通知，逐项显示状态、耗时和修复建议 |
| 自检与修复 | 连接失败时自动执行：定位失败项 → 探测 `open.feishu.cn:443` → 重启桥接订阅（`sender.ps1` / 计划任务）→ 复查连接，每一步结果都留在看板上 |
| 事件记录 | 上线、断线、恢复、修复、消息发送的时间线 |
| 操作 | 立即检测、一键排查修复、发送测试消息、断开连接 / 恢复连接 |

## 手动断开与恢复

用不上的时候不用关 DSH：点开胶囊 → **断开连接** → 再点一次确认，飞书链路立刻静默。

- 停用 Windows 计划任务 `FeishuCLIBridgeSender`：不再每分钟拉起订阅，也不再发送排队消息。
- 结束 `lark-cli event consume` 订阅进程并停止事件总线守护进程：飞书消息不再进入 DSH。
- 暂停 `pauseSchedules` 里配置的 DSH 定时任务（按标题前缀匹配，默认空）：否则值班轮询会继续按点唤起会话。
- 断开期间看板**不检测、不自动修复、不发上线/中断通知**；胶囊变灰显示“飞书 · 已断开”，断开前的记录仍留在看板里。
- 断开状态写在本机 `state.json`，重启 DSH 后仍然是断开状态；不会因为一次轮询又自己连回去。

点 **恢复连接**：重新启用计划任务 → 运行 `sender.ps1`（重新订阅并清空待发队列）→ 恢复定时任务 → 复查连接，胶囊回到“已连接”。

注意：断开期间发到机器人的飞书消息不会补发（飞书不重投）；断开超过刷新令牌有效期（7 天）后需要 `lark-cli auth login` 重新扫码。

### 断开 / 恢复也会发通知

两个方向都会往飞书发一条，走的是发送通道（不依赖事件总线，所以断联后仍然发得出去）：

```
🔴 飞书连接已手动断开
时间：21:52:10
事件订阅与发送已停止，这段时间发来的消息不会补发。
恢复：DSH 左侧栏「飞书」→ 恢复飞书连接。
```

```
🟢 飞书连接已恢复
时间：22:04:31
断开时长：约 12 分钟
连接状态：正常（7 项检查通过）
在 DSH 里可以继续收发消息了。
```

恢复通知里的连接状态取自**恢复后立刻做的全量复查**；如果那时还有异常，标题会变成 🟠 并列出失败项。看板的「上线通知」一项也会跟着显示「手动恢复通知已发送（22:04:31）」，不再固定停在启动时间。

不想要某一条：`notifyOnDisconnect: false` / `notifyOnReconnect: false`。发送失败只记在看板里，不会打断断开或恢复本身。

## 关掉浮窗（只留引擎）

装了 [dsh-feishu-board](../dsh-feishu-board)（左侧栏整页看板）之后，右下角的胶囊就多余了。把 `showCapsule` 设为 `false`：

- 浮窗不再渲染（连首次加载的「检测中」都不会闪一下）；`shell.overlay` 里不再有任何东西。
- 宿主半边照常工作：每 30 秒检测、断线自动修复、手动断开/恢复、上线通知全都在，`/feishu-observer/*` 接口也照旧，侧栏页面继续读它。
- 想看回浮窗：把 `showCapsule` 改回 `true`（或删掉这一行），重载插件即可。

代价只有一个：宿主短暂读不到状态时，原本会用「飞书 · 看板离线」的灰胶囊提示，现在什么都不显示——因为客户端要先拿到一次快照才知道该不该画。侧栏页面里仍有「找不到连接看板服务」的明确提示。

## 启动通知

每次 DSH 启动（插件激活）后约 2 秒，会向配置的飞书会话发送一条上线通知，包含时间、连接摘要和 DSH 地址。连接恢复时发送恢复通知；运行中连接中断时，若发送通道尚可用，会发送中断告警。**启动时就已断开**的情况由上线通知自身标明“连接异常”，不会重复发一条告警。

- 通知目标：`chatId`（接收通知的飞书会话；留空则所有通知静默，检测与操作照常）。
- 每次 DSH 进程启动只发送一次；插件热重载不会重复发送。可用 `onlineCooldownMinutes` 额外限流。
- 关闭通知：把 `notifyOnStart` 设为 `false`。

## 连接检查的判定

| 检查 | 数据来源 | 什么时候算失败 |
| --- | --- | --- |
| lark-cli 工具 | 文件是否存在 | 找不到 `lark-cli.cmd` 或其 Node 入口 |
| 飞书授权 | `lark-cli auth status` | 机器人身份或用户授权不可用；用户授权只在**刷新令牌**到期（默认 7 天）前 3 天提示续期 |
| 事件长连接 | `lark-cli event status` | 总线未运行，或没有活跃消费者 |
| 桥接发送器 | `feishu-bridge/status.json` | 心跳超过 10 分钟未更新 |
| 开放平台接口 | `lark-cli im +chat-list` 探测 | 接口不可达（默认 120 秒缓存一次） |
| 消息入站 | `feishu-bridge/events/*.json` 最新时间 | 仅提示，超过 24 小时无入站会变黄 |
| 上线通知 | 本次启动的发送结果 | 仅提示 |

## 配置

在 `cordis.patch.yml` 的 `feishu-observer` 行里修改：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `chatId` | `'` | 接收通知的会话（`oc_...`）。留空时上线 / 断开 / 恢复通知都不会发 |
| `chatLabel` | `'` | 看板里显示的通知目标名；留空回退到 chatId |
| `larkCli` | `'` | lark-cli 入口；留空则从 PATH 查找 `lark-cli.cmd` / `lark-cli` |
| `bridgeDir` | `'` | 桥接目录（`status.json`、`events/`、`sender.ps1`）；留空为 `<DSH_HOME>/feishu-bridge` |
| `pollSeconds` | `30` | 自动检测间隔 |
| `probeSeconds` | `120` | 接口探测缓存时间 |
| `onlineCooldownMinutes` | `0` | 上线通知额外限流（0 表示每次启动都发） |
| `notifyOnStart` | `true` | 启动时是否发上线通知 |
| `notifyOnRecover` | `true` | 恢复时是否发恢复通知 |
| `notifyOnBreak` | `true` | 中断时是否尝试发告警 |
| `notifyOnDisconnect` | `true` | 手动断开时是否发一条“已断开” |
| `notifyOnReconnect` | `true` | 手动恢复时是否发一条“已恢复”（含断开时长与本次检查结果） |
| `senderTask` | `FeishuCLIBridgeSender` | 手动断开时停用、恢复时启用的计划任务名 |
| `pauseSchedules` | `[]` | 手动断开时一并暂停的 DSH 定时任务（按标题前缀匹配） |
| `showCapsule` | `true` | 是否显示右下角浮窗胶囊。设为 `false` 后本插件只做引擎，界面交给 `dsh-feishu-board` 的侧栏页面 |

## 数据与边界

- 看板状态只保存在本机 `%DSH_HOME%/feishu-observer/state.json`，不上传任何地方。
- 消息发送与状态读取都通过本机 `lark-cli` 完成；插件本身不联网、不读取飞书凭据。
- 所有检测命令都在**隐藏控制台**中执行（`wscript` + 隐藏 `cmd`，并直接调用 `lark-cli.exe`，不经过会弹出控制台的 npm 包装脚本），所以每 30 秒一次的检测不会在屏幕上闪窗口。
- 用户访问令牌（约 2 小时有效）会由 `lark-cli` 用刷新令牌自动续期。看板看到 `needs_refresh` 时，会主动做一次用户接口调用把令牌刷新掉，并把刷新令牌的有效期往后顺延（每次续期 = 从此刻起 7 天）。所以只要 DSH 经常开着，授权不会自然过期；超过 7 天没用才需要 `lark-cli auth login` 重新扫码。
- 自动修复只覆盖可以安全重启的桥接订阅与计划任务；**授权失效需要人工扫码**（`lark-cli auth login`），看板会明确提示。
- 看板接口为同源本地 HTTP 路由 `/feishu-observer/*`，只接受带 `x-dsh-feishu: 1` 头的请求，且服务仅绑定本机回环地址。
- 修改配置或升级插件后需刷新 DSH 页面以重新加载客户端模块。
